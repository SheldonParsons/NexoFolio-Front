你提出业务问题，Agent 自己决定怎么查。NexoFolio 把接口资料组织成可以逐层展开的知识库，让 Agent 按需找到相关内容，需要核实时还能继续查看完整说明和原始依据。

## 你说目标，Agent 决定怎么找

- 只需说明项目、环境和想解决的问题，不用提前找 ID，也不用安排工具调用顺序。
- MCP 连接时提供整体使用说明，介绍有哪些资料、怎样继续展开，以及这些结构能帮助解决什么问题。
- Agent 可以浏览业务目录，也可以搜索接口、路径或字段含义；从哪里开始、沿什么线索继续、查到多深，都由它根据任务决定。

## 按需展开，少读无关内容

- 找到目标字段后，可以直接读完整说明，省去重复打开接口概览的步骤。
- 字段说明提到其他接口时，可以顺着已有引用或文字线索继续查找。已有明确来源时，可直接查看对应请求、响应和采集背景。
- 没有子项的字段不再提供空的展开入口；需要更多细节时，完整说明、关联依据和实际观测值仍可继续读取。
- 减少无关内容和重复读取，同时保留深入核实的能力；问题需要全貌时，也可以扩大范围或完整读取。

## 查到了什么，还缺什么，更容易分清

- 可以查看资料缺口的整体情况，也可以直接查看某类问题或某个字段，不必翻完所有明细。
- 分开说明“内容是否已生成”“业务含义是否已确认”“原始调用是否采集完整”，避免把待确认说明误解为整理失败。
- 保留来源、环境、时间和确认状态，帮助 Agent 判断证据能支持到哪一步。样本里的值相同，不代表已经确认唯一来源或必须按某个顺序调用。
- 长资料可以分段继续读取；参数填写不合适时，会给出允许范围和调整提示。

## 复制一段话，让 Agent 理解并接入

- “让 Agent 帮你接入”的开场同时带上当前服务地址、使用理念和检索原则，让它先理解这套资料结构，再完成配置和读取验证。
- 补充了了解陌生项目、查任务 ID 来源、从字段说明找相关接口、检查资料缺口等提问示例。
- 网页与可直接交给 Agent 阅读的完整参考同步更新；地址按当前环境填写，无需手工替换示例域名。

目前提供 11 个只读工具，用于查阅已授权的接口知识，不会替你发送业务请求或修改资料。
