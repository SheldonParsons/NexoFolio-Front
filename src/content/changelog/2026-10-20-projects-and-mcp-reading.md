这次让项目更好找，也让 Agent 更容易读到需要的字段和真实依据。项目空间增加最近整理与整理人，MCP 增加可选的正文读取和字段分组，下载渠道与页面加载反馈也一起完善。

## 项目更好找，最近整理一眼可见

- 最近访问增加到 5 个，方便回到常用项目。
- 可以按项目名称模糊搜索全部项目，搜索与分页使用同一份结果；移除权限筛选下拉框和原来的项目状态列。
- 新增“最近整理”和“整理人”，对应同一轮整理。没有整理记录时显示“无”，整理人优先显示昵称，没有昵称时显示账号。
- 排队、正在整理和等待重试的项目优先展示；正在整理的状态缓慢闪烁，减少动态效果的系统设置仍受支持。
- 整理完成后显示本轮开始的日期与时间，使用北京时间。历史记录缺少开始时间或整理人时明确标为未知，不用结束时间或当前用户代替。
- 长项目名称、整理人和时间在窄屏中妥善收起，仍可查看完整内容。

## MCP 按需读取，减少重复内容

- 请求和响应可以选择只读取完整的解析正文，避免将原文与解析结果重复带入上下文；完整原文与同一条采集记录的展开入口仍保留。
- 字段搜索可以按接口分组，共用目录和接口信息，每个字段仍有完整说明、精确位置和独立展开入口。
- 精确字段名称优先于仅在说明中出现的关键词，减少寻找目标字段时的干扰；全部匹配仍可继续翻页查看。
- 历史样本已经不在保留范围时，明确说明缺失，并提供当前接口的样本索引，方便继续查找；不会用另一份样本冒充原始依据。
- 精简工具公共说明中的重复内容。目录、搜索、字段、关系和样本仍可自由选择，没有固定调用顺序；原有读取方式继续兼容。

## 同资料检查与真实 Agent 对照

在相同资料、相同排序的同一页 50 个字段中，按接口分组后的返回内容从 **50,348 → 35,804 字符，减少 28.9%**。全部 59 个匹配通过分页核对，无遗漏，字段说明和展开入口继续保留。

一组包含 226 条数据的正文，选择解析正文后，从 **6 块降至 3 块**完成读取，完整解析值核对一致。

另用相同模型（gpt-6.1-sol，medium）、相同问题、同一份冻结资料及相同 CLI 配置，完成两道题各一次优化前后真实 Agent 对照。Agent 自主决定检索路线：

| 场景                 | MCP 调用次数：优化前 → 后 |       累计返回字符：优化前 → 后 |  耗时：优化前 → 后 |
| -------------------- | ------------------------: | ------------------------------: | -----------------: |
| 产品分类、系列与型号 |                   33 → 27 | 243,033 → 175,821（减少 27.7%） |  101.19 → 83.54 秒 |
| 服务类型与业务子类型 |                   63 → 52 | 356,697 → 301,593（减少 15.4%） | 124.00 → 144.50 秒 |

四份答案的关键内容与证据边界核对通过，均无重复读取。第二题前后各出现一次样本读取错误，Agent 都通过本接口的样本索引恢复，没有将缺失样本假称为已经读取。

以上为隔离环境中的只读检索，使用已保存资料，未向实际业务系统发送请求。返回量减少不代表每道题都更快：第二题耗时增加，且检索路线与读取范围也有变化，不能把整题差异全部归于格式压缩。字符不等于模型 Token 或费用；本轮结果也不与此前不同版本、不同宿主的成绩合并计算。

## 下载渠道与页面恢复更清楚

- Fetcher 下载入口可以独立选择“Gree 内部版 / 公网版”，与 AsyncTest 的渠道选择互不影响；版本和下载地址对应当前选中的渠道。
- 修复新版网页读取下载信息时的兼容问题，避免 Fetcher 和 AsyncTest 下载入口一起显示不可用。
- 版本更新后，旧标签页遇到页面资源加载失败时，会明确提示并提供重新加载目标页面的入口，避免点击菜单后只闪一下、没有后续反馈。
- 重新加载由用户确认，方便先处理当前页面尚未保存的内容。
