## 让 Agent 理解项目接口

当 Agent 协助开发时，它需要的不只是一个请求地址。接口属于什么业务、字段说明来自哪里、不同环境有什么差异，这些上下文都会影响它的判断。

NexoFolio 希望通过 MCP，让支持该协议的 Agent 能够围绕项目读取接口知识，并保留对原始依据的追溯。

## MCP 的定位

MCP 为应用向 Agent 提供工具与上下文建立了统一的交互方式。在 NexoFolio 中，它承载的是知识的使用入口。

你可以把它理解为：让 Agent 沿着项目的知识结构，找到接口、读取资料、了解依据，而不必从零开始猜测。

接入资料的工具与使用知识的 Agent 可以不同。Fetcher、开放 API 与 MCP 各自承担不同的工作。

| 入口              | 主要职责                     |
| ----------------- | ---------------------------- |
| NexoFolio Fetcher | 为浏览器场景采集并接入资料   |
| 开放 API          | 支持其他工具与系统按约定接入 |
| MCP               | 面向 Agent 的知识访问方向    |

## 知识仍然有边界

Agent 需要区分实际观察、推断和待复核的信息，也需要知道资料所对应的项目、环境与版本。

模型生成的解释不自动成为新的独立证据；目录或语义候选也不会因为 Agent 读取了它，就自动发布。
