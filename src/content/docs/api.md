## 为什么开放接入

NexoFolio Fetcher 为浏览器场景提供了一个官方入口。但接口知识也可能来自自建采集器、内部工具或已有工作流。

开放 API 是这些接入方式之间的共同边界。接入方提供资料及其归属，NexoFolio 负责按约定接收和组织这些资料。

## 接入需要哪些信息

| 内容               | 作用                             |
| ------------------ | -------------------------------- |
| 项目与环境         | 确认记录归属，区分不同运行场景   |
| 接入身份与权限     | 确认调用者可以向目标项目提交资料 |
| 记录与批次标识     | 区分新记录和同一请求的重试       |
| 请求、响应或上下文 | 保留实际观察到的内容及其限制     |

涉及截断、缺失或无法采集的资料，应保留对应状态，不补造原始内容。

## 先读取能力，再提交记录

当前接入协议提供能力查询与批量提交入口。具体服务地址与凭证由部署方提供。

```http
GET /v1/ingestion/capabilities?schema_version=3
POST /v1/ingestion/batches
```

接入方先了解服务支持的协议、内容类型和大小限制，再按照对应约定提交记录，并根据收讫结果处理重试。

记录被接收、接口完成处理、知识被审阅和候选被发布，是不同的状态，需要分别理解。
