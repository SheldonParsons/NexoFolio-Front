# 项目内接口文档

当前入口为 `/projects/:projectId/interfaces`。保留项目列表已有布局、动效与返回恢复；项目内使用固定头部、左侧接口列表和右侧内容面板，只有内部区域滚动。窄屏在列表和详情之间切换。

## 契约来源

- 文档：`src/contracts/documents/1.0.0/`。
- 环境和原始采集 fixture：`src/contracts/ingestion/2.0.0/`。
- 复制自后端当前工作树。manifest 中的全部文件及生成 TypeScript 类型都核对了 SHA-256，副本与源 manifest 保持一致。
- 固定 bundle 排除在 Prettier 外，禁止手改生成字段。运行时使用 Ajv 2020-12 和格式校验，不把 TypeScript 类型当成运行时验证。

## 展示流程

1. 打开项目后核对项目准入，读取环境第一页（100 条）。环境必须手动选择，不从域名推导，不自动选第一项；超过一页可以继续加载。
2. 选择环境后读取接口列表（每页 20 条），全部显示在真实的“待分类”分组中，不生成伪业务目录。
3. 搜索调用服务端 query，只匹配当前环境中 method/path 的大小写不敏感字面子串；限制 500 UTF-8 字节。组合输入期间不查询，停止输入 250ms 后查询，Enter 立即提交。
4. 点击接口读取当前环境观测定义，展示请求 Query 参数、头名称/类型、正文结构，响应状态/采集状态/头/正文结构、限制说明、版本和来源。
5. 点击“调用样例与差异”才读取观测摘要；点击具体样例或“查看源样例”才读取 ObservationDetail。列表不批量加载 raw_record。
6. 样例原文以只读 JSON 展示，保留所有原始字段和值，不脱敏、不截短，不使用 HTML 渲染采集内容。
7. 差异显示为“待处理差异／未应用”。只有 compared_revision_id 与当前 revision_id 一致时才展示当前定义对照；不一致时仅展示提议并说明无法准确对照。没有接受、覆盖、裁决、编辑、删除或重处理按钮。

“重新读取列表／定义／状态”只执行 GET，不是重试后台处理任务。

## 观测边界

页面不生成业务中文含义、必填规则、枚举或确认状态。null、空数组、非 JSON、截断和提取限制按后端给出的 observed_schema/limitations 展示。HTTP 状态码单独呈现，不被当作业务成功。

结构表格最多渲染 400 个节点、32 层；参数/头表格最多展示 400 项，超出时有说明，完整定义与结构 JSON 仍可展开。原始样例使用浅引用和单个只读文本区域，不创建逐字段深响应代理或自动持久化到本地。

## 异步与权限

项目、环境列表、接口列表、定义、观测摘要和样例分别管理 AbortController，并检查请求身份及项目生命周期。环境/接口切换清理旧定义和样例，旧返回不能写入新选择。分页或查询变化也会取消旧选择；数据总数收缩时退到有效页。

所有真实读取使用内部 Bearer，并带 no-store。401 引导重新登录；403/503 保留登录态并显示对应错误；404 提示返回列表选择。响应除了 Schema 校验，还检查项目、环境、接口、记录 ID 和分页是否与请求匹配。

需要契约示例时将两项一起设为 mock；示例模式显示“契约示例”，不绕过登录守卫。示例包含两个环境、24 个接口、当前基线、结构不变样例、未覆盖基线的差异、null、空数组、非 JSON 与截断正文。真实请求失败不会回退为示例数据。
