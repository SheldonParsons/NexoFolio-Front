# 收集接口文档页

`/docs/api` 从“开放 API 概览”改为收集接口（`POST /v1/collect/batches`）的完整接入文档，面向自己写采集工具的开发者。

## 内容来源

- 正文是 `src/content/docs/api.md`，按“什么时候使用 → 快速开始 → 批次 → 归属 → 记录 → 内容状态 → 校验 → 回执 → 错误与重试 → 限制 → 合同文件”组织。
- 合同来自后端 `contracts/collect/v1`，原样复制到 `src/contracts/collect/1.0.0` 并按 manifest 校验哈希。页面上的上限、版本号从 manifest 读取。
- 正文里的 JSON 示例由 `tests/collect-contract.test.ts` 按 batch、receipt、error schema 校验，文档和合同不会悄悄分叉。示例中的地址和 ID 都是虚构的。

## 页面结构

沿用产品文档的黑白阅读布局，不引入新的字体或色板。三处和其他文档不同：

- 标题下方是接口块：反色的 `POST` 标记、较大的等宽路径和复制按钮，下面一行写请求体、鉴权、合同版本，最后一行如实说明“合同已定稿，服务端接口尚在开发中”。
- 正文中的 `<!-- collect-workbench -->` 位置插入校验工具，这是本页唯一的重点元素。左侧列出合同自带的 4 个可通过样例和 25 个常见错误，右侧是可编辑的 JSON；输入后在本地用 Ajv（draft 2020-12）按同一份 schema 校验，给出中文原因和字段路径（如 `records[0].payload.request.method`），同时计算请求体和单条记录的大小。结果区域是 `role=status`，内容不离开浏览器。项目和环境是否存在只能由服务端判断，页面上写明了这一点。
- 宽屏（≥1360px）右侧有“本页内容”，跟随滚动高亮当前章节；窄屏隐藏。

失败状态使用单独的红色（浅色 #d1242f，深色 #ff6369），只出现在校验结果和错误样例的标记上。

## 边界

只改了文档页与其内容，没有改动首页、部署文件等已有的未提交修改。收集接口本身尚未实现，本页不发送任何请求。
